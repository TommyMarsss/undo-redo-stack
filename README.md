# 撤销/重做命令栈（支持操作合并）

原生 JavaScript（HTML/CSS/JS 单文件，零框架、零依赖）实现的文本编辑撤销/重做系统，
对**插入、删除、替换**三类操作建模为命令对象，重点解决：

1. 连续相似操作（如连续敲入一个短语）合并为一个撤销单元；
2. 撤销后产生分支（执行新操作）时，重做栈必须整体清空；
3. 每类命令都能生成精确逆操作，多轮“操作 → 撤销 → 重做”后文档与每一步中间态完全一致。

## 运行

- **演示页面**：浏览器直接打开 `index.html`（左侧编辑，右侧实时显示双栈调试面板）。
- **自动化测试**：

  ```bash
  node test-runner.mjs
  ```

  启动器会从 `index.html` 中抽取内嵌的同一份引擎脚本在 Node VM 中执行，
  页面里点“运行自动化测试”按钮可得到相同结果（13 个用例）。

## 命令模式设计

```
TextDocument   文本模型，唯一真值。只暴露 insert / remove / replace 三个原语。
Command        命令接口：apply(doc) 执行；inverse() 生成精确逆命令。
 ├─ InsertCommand  (pos, text)        inverse → DeleteCommand(pos, text)
 ├─ DeleteCommand  (pos, text)        inverse → InsertCommand(pos, text)
 └─ ReplaceCommand (pos, old, new)    inverse → ReplaceCommand(pos, new, old)
History        双栈管理器：undoStack / redoStack + 合并判定 + 时钟注入。
```

### 双栈流转规则

| 动作 | undoStack | redoStack | 文档 |
|---|---|---|---|
| `execute(cmd)` 新操作 | `apply` 后尝试与栈顶合并，否则压入 | **整体清空（分支丢弃）** | 执行 `cmd` |
| `undo()` | 弹出栈顶命令 | 压入**原命令** | 执行 `原命令.inverse()` |
| `redo()` | 压回**原命令**（不二次合并） | 弹出栈顶 | 重新 `apply` 原命令 |

两个关键正确性决策：

- **撤销时入重做栈的是原命令而不是逆命令**：重做只需重新 `apply` 原命令，
  往返过程中命令对象不变，逆操作只在撤销瞬间生成并执行一次。
- **重做不参与合并**：被时间间隔拆开的两个单元，撤销再重做后仍然是两个独立单元，
  不会因为重做时“相邻”而被意外粘连。

### 精确逆操作

- 插入 `Insert(pos, text)` 的逆是同位置等长删除；合并后的插入逆操作一次性删掉整个短语。
- 删除 `Delete(pos, text)` 保存了**被删掉的原文**，逆操作把原文逐字还回原位；
  连续 Backspace 向前合并后，一次撤销即可还原整段。
- 替换 `Replace(pos, oldText, newText)` 的逆仍是替换，新旧文本互换
  （等长替换与变长替换都成立）。

测试“插入/删除/替换混合 3 轮”记录了前向路径的每一中间态，
随后做 3 轮完整撤销/重做并逐状态比对，保证往返无损。

## 合并判定规则

新命令 `next` 入栈时，与撤销栈顶 `top` 依次检查，**全部满足才合并**；
命中第一条失败原因即另起一个撤销单元（失败原因会显示在调试面板）：

1. **类型相同**：插入只与插入合并，删除只与删除合并。插入后紧接删除不合并
   （`type-mismatch`）。替换命令始终原子，永不合并（`replace-atomic`）。
2. **双方都是单字符操作**：粘贴/输入法整段结果等多字符命令不参与合并，
   并且会终止合并链——其后的单字符也不会并进多字符单元（`multi-char`）。
   判定方式：`next.text.length === 1` 且
   `top.text.length === top.mergedCount`（既有单元全部由单字符组成）。
3. **长度上限**：合并后不超过 64 字符，防止超长单元（`too-long`）。
4. **时间窗**：`next.timestamp - top.timestamp ≤ 500ms`。
   合并后单元时间戳更新为最后一次按键时间，因此以“最后一次击键”为窗口起点，
   正常连续输入可以一直合并，停顿超过 500ms 即断链（`timeout`，边界 500ms 仍合并）。
5. **位置相邻**：
   - 插入：`next.pos === top.pos + top.text.length`（紧跟在后面输入）；
   - 删除：`next.pos + next.text.length === top.pos`（连续 Backspace 向前删）。

   鼠标点到别处再输入、Forward Delete 等位置不相邻的情况不合并（`not-adjacent`）。

合并算法本身是 O(1) 的（仅看栈顶一条），合并单元内部用 `mergeWith` 做文本拼接：

- 连续插入：`pos` 不变，`text = top.text + next.text`；
- 连续 Backspace：`pos = next.pos`，`text = next.text + top.text`。

## 分支操作后重做栈清空

`execute()` 的最后一步无条件执行 `redoStack.length = 0`。

这是命令栈最经典的正确性陷阱：撤销若干步后历史出现“分支”，若此时执行新操作
却保留旧重做栈，用户之后重做时会把已经不属于当前文档的旧命令重新执行出来。
测试覆盖两种情形：

- 撤空后输入新字符：重做栈立即为 0，`redo()` 返回 `null`，旧内容永不复活；
- 只撤销一步即输入：撤销链回到正确的中间态，重做栈只保留新分支命令，
  一路重做也只会得到新分支结果。

## 调试面板

右侧实时展示：

- 模型真值（当前文档 JSON，便于看清空格/换行）；
- 上次入栈是“已合并”还是“独立新单元”，以及具体的合并/拒绝原因；
- 撤销栈、重做栈的完整命令列表（类型徽标、位置、内容、`合并 ×N` 标记，
  栈顶高亮）、栈深计数与按钮可用状态。

## 浏览器适配说明

- `input` 事件通过对比编辑前后的字符串做公共前缀/后缀差分（`diffEdit`），
  把一次 DOM 变更还原为一条插入/删除/替换命令，因此不依赖具体按键事件。
- 输入法（IME）组字期间（`compositionstart/end`）不入栈，整段上屏作为一个
  原子多字符命令，避免拼音组字过程污染撤销历史。
- 快捷键：`Ctrl/⌘+Z` 撤销，`Ctrl/⌘+Shift+Z` 或 `Ctrl+Y` 重做。
- “单字符”按 UTF-16 码元计数，多码元字符（如部分 emoji）按原子多字符处理。
